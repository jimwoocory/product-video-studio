# Product Video Studio · UX-R0 独立原型

## 访问

在本机执行：node prototypes/ux-r0-workbench/preview-server.mjs

默认打开：http://127.0.0.1:3195/

这不是 Product Video Studio 的正式网站（正式服务习惯使用 3090），不能用来操作真实项目。原型的状态只存在浏览器内存，刷新会恢复默认演示状态。

## 三种业务场景

1. 新建产品视频：保存产品资料 → 核对可用产品事实 → 选择创意 → 查看正常后继步骤。可选研究/参考材料直接在当前页面折叠展开，不使用完整页 iframe。
2. 镜头审片：从第 2 段开始，演示采用镜头、仅重做当前镜头（修改提示词 → 新费用授权确认 → 候选再审），完成后查看后期剪辑方向。
3. 资产失败：人物 B 明确失败时，编辑提示词 → 模拟付费确认 → 查看模拟候选 → 确认继续；可切换成“提交结果未知”，此时必须查原结果，不可重复付费提交。

## 不触碰真实业务的隔离边界

- 静态 HTML/CSS/JavaScript，不引入正式 src 或数据库。
- 全部数据为模拟数据，内容明确标识为演示；用户可仅在本地预览选择的图片。
- HTTP 只允许 GET/HEAD 访问 4 个静态页面文件；其余返回 404/405。
- CSP 明确禁止网络连接和 iframe 完整页嵌套。
- 不产生任何 Seedream/Seedance 积分、抖音发布/评论操作，也不会改变原始 PVS 的 SmartRun、项目状态或文件。

## UX-R0 评审重点

- 用户是否能在首屏找到当前唯一主动作？
- 三种不同目的是否不再出现六个入口与实际待办争抢优先级？
- 提交核对/审核后是否自动切换到下一状态，而不是用户自己找下一页/点击刷新？
- 局部重做是否明确影响范围，并与真实付费确认分离？
- 旧版完整专业功能将来作为“高级编辑”保留，但不在主界面默认铺开。

离线备用：standalone-preview.html 集成了全部样式和脚本。即使预览服务停止，也能在本机直接双击该文件（或使用 Chrome 的 file:/// 地址）继续体验。

Chrome 自动化验收：node prototypes/ux-r0-workbench/verify-prototype.mjs。脚本仅调用本机静态原型并生成截图，覆盖三种场景、费用确认、异常恢复及 390px 窄屏。

**重要：** 本原型只是页面与交互设计方案。实际生产代码需要用户批准后按 UX-R1～R5 单独实施。
